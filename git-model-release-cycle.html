Proposal for large projects

An epic branch for large-scale projects

  1. An epic/* branch created from develop
  2. Each story branches off the epic and returns to it after BA / UX testing
  3. Regular sync from develop to the epic
  4. End-to-end acceptance on the epic environment
  5. Merge into develop once the epic is ready for a release

Six rules to keep in mind

master is production

Never commit on master: it only receives merges, at the go live of an rc or a hotfix.

Validate before merging

BA / UX testing, plus UAT when required, before any merge into develop.

After cut-off

Only fixes reach the rc, through bugfix branches created from it.

After package freeze

No more changes: any change means a new package.

Always carry over

Every fix, on the rc or as a hotfix, is carried over to develop.

Test what we ship

NRT, perf and rehearsal run on the frozen package.

Shortening our delivery lead time

Automate NRT

Non-regression runs in hours rather than days.

Industrialise deployment

A rehearsal that can be replayed on demand, identical to go live.

Feature flags

Deploy without switching on: the business go / no-go becomes a simple toggle.

Shorter branches

Smaller stories, merged more often, with fewer conflicts.
