# Merging the Architecture board into the production vision (Docs › Architecture)

**Done on 2026-11-03.** The production vision's Docs › Architecture space is now the Architecture board (Meridian
Bank), generated into `ProductionVision.dc.html` by the build (section 4), with the three things the Docs lab had
and the board lacked: the Grid · Diagram switch, the view navigation (crumbs, Back, drill-down history) and the
element card on click. Decisions DEC-KB-34..36 are adopted; DEC-KB-37 is adopted for the example, not yet for the
detailed-design pages (section 7).

## 1. What the production vision did before (Docs lab, corporate credit example)

Flow: Docs › Spaces › Architecture card › subheader "‹ Corporate credit platform · 133 elements · 13 views · 3 plateaus ·
main @ sha" › tabs Catalogue · Views · Process. Views: a side list grouped by TOGAF ADM phase with drill-down views
indented under their parent; the view header (phase kicker, title, one-line sub); a tools row (plateau segmented
Baseline · Transition 1 · Target · Gap, then the gap pair); the **LikeC4-style canvas**: a floating panel (LikeC4 mark,
back arrow, crumbs `corporate-credit › Application cooperation › Inside Credit origination`, view id), a zoom group
(+ − Fit), the hand-laid diagram (ArchiMate figures, routed lines with relationship markers and labels, groupings),
and on selection the **element card** docked top-right inside the frame: type tile, name, kind, change chip (in a
gap), description, plateau track, owner, origin, "In this view" (every relationship of the element in this view,
each a button that selects the neighbour), "Open the view …" (drill-down, also a ↗ button on the figure), "Open in
the catalogue", "Detailed design". Under the frame: legend of the kinds and relationship lines used, "Generated by
LikeC4 from … · drawn with the AIToolbox ArchiMate notation", "Show the view source". Going down keeps a history:
back returns to the parent view with the element that was selected; crumbs jump up; migration plateaus open the
landscape on that plateau. DD pages (hexagon, state machine, data model, API) open from a hexagonal view.

Kept: the frame chrome (crumbs, back, view id, zoom), the selection model (select → card → neighbours →
drill-down), the view history, the source link, the DD pages, the legend built from what the view uses.
Dropped: views only as drawn diagrams, one example application, side list by phase (DEC-KB-32), four-step changes
(DEC-KB-30), no matrices, no catalogue tree.

## 3. The merge, as built

### 3.1 One view frame, two renderings (DEC-KB-34)

Every view of the Views area sits in one frame (`.vframe`):

| Part | Content | From |
|---|---|---|
| Head | level kicker and phase, title, For · Decides, How to read | board |
| Tools | plateau segmented (B · T1 · T, gap pair when the view has gaps), the view's own controls, and a **Rendering** segmented **Grid · Diagram** on the views that have a diagram | board + new |
| Panel | mark (`Grid` or `Diagram`), Back arrow when there is history, crumbs from the enterprise (buttons), view id, zoom + − Fit in Diagram | Docs lab |
| Body | Grid: the matrix / grid / timeline / cards of the board. Diagram: the SVG of the same view, figures as buttons | board / gen_graphs |
| Card | the element card on selection, same content in both renderings | Docs lab |
| Foot | "Generated from model/… · main @ sha"; Show the view source | Docs lab |

Diagram is available on motivation, value streams, application cooperation, gap (per gap), requirement chain and
inside-and-neighbours; Grid is the default everywhere and the choice is remembered per view in the state (`rend`). The
diagram is a static SVG per view and plateau from `gen_graphs.py` (lane layout, ArchiMate markers); in the product
it would be `likec4 export svg` with the AIToolbox skin — no LikeC4 runtime in the page.

### 3.2 Selection and the element card (DEC-KB-35)

Clicking a figure in a grid cell, a matrix row head or a diagram node selects it (`sel`): every figure of that
element in the view gets the selected ring (`.ax-sel` under `.selwrap.sel-<sid>`). The card docks on the right of
the frame from 1200 px and stacks below under it. Content: type tile, name, kind, change chip, description, plateau
track, owner, origin, **In this view** (the element's relations whose other end is in the view, as sentences —
"serves Verify identity", "flows to Facility API" — each a button that selects the neighbour), **Open the view …**
when the drill-down map has a target, **Open in the catalogue**. Escape or ✕ closes. The element page stays one click
further (the catalogue), never the first click from a view.

### 3.3 Drill-down, crumbs and back (DEC-KB-36)

`navigateTo` by element kind and level: enterprise capability → portfolio landscape; application component → inside
and neighbours of its application; business process → processes × applications; requirement → requirement chain; work
package or plateau → roadmap / gap. The history stack `vhist` holds `{level, view, pf, app, plateau, rend, sel}`
(`snap()` / `drill()` / `back()`); Back restores all of it; crumbs are buttons; the side list follows the current
view (the level picker switches when a drill-down changes level).

### 3.4 Areas and the rest

Catalogue and Process come from the board as decided (DEC-KB-31, 33, 30). The Docs lab's ADM-phase list is gone;
the phase stays as the kicker of each view head. The ARB page with the 13-item ASD comes from the board, with an
"Act as" row (owner · reviewer · chair · reader) in the Decision tab, since the vision has no "view as" for these
roles. Entry and shell unchanged: Docs › Spaces › Architecture, subheader back to Docs, the header's search-or-ask
field is the catalogue's search while the catalogue is open and the header context reads "Docs · Architecture ·
Catalogue · 227 elements" (or the current view / change).

### 3.5 Example (DEC-KB-37)

One example in the space: Meridian Bank. The corporate credit example's hand-laid diagrams are retired from the
vision; the Docs lab board stays on the canvas for the record.

## 4. Build

`tooling/vision_arch.py` turns the board into a part of the vision: the board's markup with its hole keys prefixed
`ar_` (aliases of `sc-for` kept), wrapped in `<sc-if value="{{dl_vArch}}"><div class="ar">…`; the board's CSS scoped
under `.ar` (`:root` → `.ar`, `main` rules dropped); the board's `Component` turned into `class ArchLogic` whose
state is the vision's `state.ar` and whose `setState` ticks the host; `archVals(ctx)` on the vision's Component
returns the board's values prefixed; `patch_vision_js` hooks `archVals` after `docsVals` and overrides the header
context when the space is open. It finds the board's generator next to it or in `tooling/architecture-board/`.
`tooling/vision_build2.py` is `vision_build.py` with the Docs lab's architecture screen replaced by `VA.SCREEN`,
`VA.CSS` appended, `VA.CLASS_JS` before the Component class and `VA.METHOD_JS` inside it. Run:
`python3 vision_build2.py ProductionVision.dc.html` (1.98 MB; `vision_build_vanilla.py` reproduces the previous vision
byte for byte, so the merge is a generated diff). The Architecture board itself is `build_arch.py` + `arch_logic.js`
+ `gen_graphs.py`; the three labs are built grid-only (no diagram blocks) on the same logic.
