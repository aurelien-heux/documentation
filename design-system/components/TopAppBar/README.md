# TopAppBar
- **Small** 64 px: leading navigation icon, title-large, up to three trailing icon buttons. On `nav-container`, the same colour as the NavigationDrawer, separated from it by a 2 px gap of the page `surface` (no outline); the navigation menu button sits at the top of the rail (or of the open drawer), not in the bar — under 600 px it is in the top bar; search field on `surface-container-lowest` (light) / `surface-container-high` (dark), avatar on `secondary-container`.
- **Medium / Large** 112 / 152 px: the title drops under the icons in headline-medium / headline-large and collapses to small on scroll.
- Icon buttons are 40 px in a 48 px slot; titles truncate with an ellipsis, never wrap in the small bar.
- **Responsive:** Under 600 px: 56 px, menu · logo mark · feature name (the summary hides) · search icon · bell · avatar (help in the user menu, assistant in the NavigationBar). 600–1199 px: 64 px, the search field flexes (240 / 320 – 440 px) with the Ask chip as an icon, avatar only, help in the user menu under 840 px. From 1200 px: 440 px search with the labelled Ask chip and the user chip with name and role.
- **Keyboard and screen reader:** the user chip's name starts with the visible name ("Aurélien Heux, platform admin, account menu") with `aria-haspopup="menu"`; at 320 CSS px the avatar stays and navigation moves to the bottom NavigationBar.
- **Angular Material:** `mat-toolbar` — never `color="primary"`. Add `class="dt-nav"`: both theme files set its `container-background-color` to `nav-container`. Medium / large bars are a custom header, not a toolbar row. Full map and theme files: `angular-material.md`.

## App header (AIToolbox shell)
Left to right: **logo** · **page context** (feature name over a one-line summary, right of the logo behind a 1 px `outline-variant` divider: label-large 600 `on-surface` / body-small `on-surface-variant`, the summary truncating with an ellipsis before the search field; e.g. "Sweep · Runs" / "staging · credit-request · 3 open pull requests", "Community · Ideas" / "Vote once per idea…") · **search-or-ask field, centred on the bar** (440 × 44, radius 16; ⌘K focuses it; Enter searches; the **Ask** chip — `ai-container`, Chatbot mark — sends the text to the assistant and opens the assistant block) · **assistant** icon button with the Chatbot mark (idle · typing dots while it writes in the background · tertiary dot when a reply waits) · **notifications**: the Notifications feature-mark bell (no dot) with an `error` count badge (1–9, 9+, 99+), ringing once when one arrives · **help** · divider · **user chip** (avatar on `secondary-container`, name title-small, role body-small, chevron → user menu: Account settings · Settings · Notification preferences · API tokens · Theme · Sign out).
- No environment chip: the environment is a page filter.
- **No page title, no breadcrumb.** The context block is the page's name: pages start with their content (filters, tabs, table), which keeps the full height for it. Page-level actions sit on the first row of the content (right-aligned, or at the end of the tab row). Going back to a parent is a **Subheader** (`components/Subheader`): back arrow, the page's title, its context and its actions in one row, never a back button on its own row.
- **One search field.** The search-or-ask field is the only search on a page and the only way to ask the assistant from it; pages never add a second search bar or Ask buttons in their content (a filter inside a list is a filter).
- Under 1200 px the user chip shows the avatar only.
- Settings is in the user menu, never in the navigation. The rail and the drawer carry neither the assistant entry nor the user block; on phones the top bar is logo · bell · avatar and the assistant is a NavigationBar destination.
