# Architecture components · ArchiMate notation and ARB review

Components of the AIToolbox design system for the Architecture feature: the ArchiMate 3.2 notation (every element and
relationship type available in Archi) and the components that prepare an Architecture Review Board (ARB) submission and
its Architecture Solution Design (ASD). Generated by `tools/build_notation.py` from `tools/notation_data.py`; the CSS is
`design-system/archimate/archimate.css`, the LikeC4 kinds `archimate.c4`, the catalog `index.html`.

## How to read this

- **Notation colours are content colours**, like chart colours: they say which ArchiMate layer an element belongs to.
  They are never used for status, selection or actions. Status stays a StatusChip (glyph + word).
- **The type decides everything**: layer → colour, aspect → shape, type → glyph. Never pick them separately.
- None of these components exists in Angular Material: they are the standalone components of `@aitoolbox/architecture`
  (`angular/architecture`, Angular 21 and 22), built on the `--md-sys-color-*` roles. Styles: `styles/archimate.css` after
  `css/tokens.css`; M2 pages without tokens.css: `atb-architecture-m2-bridge`. Icons: `AxIconRegistry` → `svgIcon="ax:<type>"`.
- Theme switch: `html.light` / `html.dark` (and the system setting), like the rest of the design system.
- Tokens: `--ax-<layer>-fill` / `-ink`, delivered as `tokens.ax.json` (W3C Design Tokens) to merge into `tokens.json`.

## Components

## Notation components

### ArchiMate figure

**Angular:** <atb-ax-figure [type]="'business-object'" [name]="…" size="m" [state]="…"> — custom component, no Angular Material equivalent; renders the .ax-box markup.

**CSS:** `.ax-box .ax-shape-<shape> .ax-l-<layer> [.ax-s|.ax-m|.ax-l]`

One architecture element drawn in its ArchiMate figure: layer fill, 1 px layer ink, type glyph top-right, name.

- Container: layer fill, 1 px layer-ink border, shape from the aspect
- Glyph: 18 px, layer ink, top-right (in the header band for objects)
- Name: Open Sans 600, 13 / 16, centred, two lines max
- Optional change chip below the figure (gap views)
- **Sizes:** S 128 × 52 (dense diagrams, 12 / 15 text); M 176 × 72 (default); L 224 × 96 (posters, 14 / 18 text)
- **States:** Default; Hover (clickable figure): primary state layer 6 %, pressed 10 %; Selected / current: 2 px primary ring, 2 px gap; Retired (gap views): 45 % opacity, name struck through, with the Retired chip
- DS rule: The type decides colour, shape and glyph; never pick them separately.
- DS rule: Shapes: active structure square, behaviour rounded, business/data object header band, contract two lines, representation and deliverable wavy bottom, artifact folded corner, product tab, motivation cut corners, value ellipse, grouping dashed.
- DS rule: A clickable figure is a link or a button with the element name as its label; a static figure is role=img.
- DS rule: Never use the layer colour for status: status stays a StatusChip next to the figure.
- **Keyboard and screen reader:** Name = element name + type ("Reservation, business object"). Focus ring 2 px primary outside the figure; on clipped shapes it follows the outline. Retired state also carries the word Retired (chip), never opacity alone.

### Type tile

**Angular:** <atb-ax-tile [type]="…" [large]="false"> or the .ax-tile class inside mat-list items and table cells.

**CSS:** `.ax-tile .ax-l-<layer> [.lg]`

The type mark before an element name wherever several types are listed: tables, lists, chips, search results.

- 20 × 20 tile (32 × 32 large), radius-xs 4 (8 large)
- Layer fill with a 1 px inset of the layer ink at 35 %
- 16 px glyph (24 large) in layer ink
- **Sizes:** 20 px in rows and chips; 32 px in page headers (element page)
- **States:** Static only: the row or chip around it carries hover and selection.
- DS rule: Always followed by the element name; a tile alone is not a label.
- DS rule: One tile per element; DD files and ADRs use the neutral code / document tile.
- **Keyboard and screen reader:** aria-hidden; the type name is in the row (column Type) or the tooltip.

### Change chip

**Angular:** mat-chip with .dt-chip-success | -warning | -error and the glyph avatar, or <atb-ax-change [change]="…">.

**CSS:** `.ax-change.new | .changed | .retired | .unchanged`

What happens to a building block between two plateaus.

- 24 px high, radius-xs, label-medium
- 16 px glyph square: + Δ − =
- AIToolbox state containers: success, warning, error, neutral
- **Sizes:** One size (24 px).
- **States:** New (success) · Changed (warning) · Retired (error) · Unchanged (neutral)
- DS rule: Shown in gap tables, gap legends, element headers; never inside a figure.
- DS rule: Computed from plateau membership, never typed by hand.
- **Keyboard and screen reader:** The glyph is aria-hidden; the word is the name.

### Plateau track

**Angular:** <atb-ax-track [plateaus]="…" [member]="…">.

**CSS:** `.ax-track > span[.on]`

Which plateaus an element belongs to, in one glance: B · T1 · T.

- One 24 × 20 cell per plateau, in plateau order
- Member: secondary-container fill; absent: dashed outline-variant
- **Sizes:** One size.
- **States:** Present · Absent
- DS rule: Same order everywhere: baseline, transitions, target.
- DS rule: The full plateau name is the cell tooltip.
- **Keyboard and screen reader:** aria-label on the track: "In Baseline, Transition 1".

### Relationship line

**Angular:** Rendered by LikeC4 (<likec4-view>) or <atb-ax-relationship [type]="…">.

**CSS:** `SVG markers: composition, aggregation, assignment, realization, serving, access, influence, triggering, flow, specialization, association`

An ArchiMate relationship between two figures, with its line style and end markers.

- 1.6 px line in on-surface (on-surface-variant for association)
- Solid, dashed 6/4 or dotted 2/3 by type
- Source and target markers by type
- Optional label: label-medium on the surface colour
- **Sizes:** One stroke width; markers scale with it.
- **States:** Default · Highlighted (selected element's relationships): 2.2 px primary
- DS rule: One relationship type per line; split or merge paths with a junction.
- DS rule: In LikeC4 the same types are relationship kinds with the same markers.
- **Keyboard and screen reader:** Diagrams have a text alternative: the Relationships list of the element page.

## Review components

### Readiness chip

**Angular:** mat-chip.dt-chip-success | -warning | -error with the tile glyph (StatusChip).

**CSS:** `.status.st-success | .st-warning | .st-error`

Whether an ARB submission can go to the board.

- StatusChip: radius-xs, state container, 18 px tile glyph + word
- **Sizes:** StatusChip size.
- **States:** Ready for the board (success ✓) · Needs attention (warning !) · Blocked (error ✕)
- DS rule: Blocked: a blocking check fails on the scope, or a required ASD section is missing.
- DS rule: Needs attention: warnings, a pending reviewer, a change request or an open condition.
- **Keyboard and screen reader:** The word is the name; the glyph is aria-hidden.

### Check row

**Angular:** mat-list with three-line items, or <atb-check-row [check]="…">.

**CSS:** `.check.pass | .warn | .fail`

One rule of tools/validate.py with its result and the elements that fail it.

- 20 px status tile
- Title (title-small) + id and level (label-medium, on-surface-variant)
- Findings: one line each, element name as a link + message
- **Sizes:** Full width of its card; rows grouped under label-medium headers (Structure, Traceability, Plateaus & gaps, Ownership & contracts, Decisions).
- **States:** Passed · Warning · Failed
- DS rule: Blocking checks fail the pull request; warnings are shown to the board.
- DS rule: Each finding links to the element page.
- **Keyboard and screen reader:** The status word is in a visually hidden span next to the title.

### ASD section header

**Angular:** <atb-asd-section [title]="…" [source]="…">.

**CSS:** `.asd-head + .src-badge.model | .ok | .warn | .err`

Title of one ASD section and where its content comes from.

- 28 px number square (surface-container-highest)
- Title: title-medium
- Source badge: From the model (secondary-container) · Written (success) · Too short (warning) · Missing (error)
- 1 px outline-variant divider under the header
- **Sizes:** One size.
- **States:** From the model · Written · Too short · Missing
- DS rule: Sections built from the model are never edited in the page: change the model.
- DS rule: Missing sections block the submission.
- **Keyboard and screen reader:** The header is an h2; the table of contents links move focus to it.

### Reviewer decision

**Angular:** mat-chip.dt-chip-* in a mat-table column; actions are mat-flat-button / tonal / stroked.

**CSS:** `.status.st-*`

A board member's decision on a submission, recorded as a Checkpoint.

- StatusChip with glyph + word
- **Sizes:** StatusChip size.
- **States:** Approved · Approved with conditions (success) · Changes requested (warning) · Rejected (error) · Pending (info) · Not required (neutral)
- DS rule: Recorded only through the Decision panel (CMD-DECIDE-CHECKPOINT); an agent never records or changes one (INV-12).
- DS rule: Approve is unavailable while blocking checks fail; the reason is shown.
- **Keyboard and screen reader:** Disabled actions use aria-disabled and keep a visible reason.
