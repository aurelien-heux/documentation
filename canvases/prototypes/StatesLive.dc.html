State marks

One construction, four states, three containers by size, one slot for loading and state. Validated 16 Oct 2026; files in the design system under assets/States, component StateMark.

1 · One constructionA state mark is the logo’s construction with the state in the badge instead of “AI”.
the logo: toolbox + AI badge
→
a state mark: the same toolbox, the badge carries the state
1 · The toolbox never changes. The night `logo-box` (lavender on dark), with its `>_` prompt — it says “AIToolbox”.2 · The badge is the state. Same corner, same cut-out as the AI badge on the logo; it takes the state colour and a symbol: ✓ success, i info, ! warning, ✕ error.3 · One grammar. Logo, loader and states share the badge construction, so a state mark is recognisably ours without repeating the brand colours in a status column.
2 · The four statesBadge in the state role with the `on-*` symbol; info uses `primary`. Light and dark: the toolbox follows the theme (night box / lavender box), the badge follows the state role.
Success · `success` badge
Info · `primary` badge
Warning · `warning` badge

3 · Where it goes: three containers, three sizesThe same state, dressed for its container. Only the size decides which of the three to use.
A · Alone, on a surface · 24–40 px. Snackbars, popin headers, inline alerts. The mark as is.B · In a circle · 56–96 px. Page and panel empty states, table-level errors. Disc in the state role (dark on light, light on dark), mark reversed, badge in the state container.C · Tiny · 18–20 px. Chips, table cells, menu items. The badge construction does not survive; the `>` + symbol on a tile in the state colour (the favicon rule) takes over.
