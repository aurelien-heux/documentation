Agent run

An agent run is one agent working on one object (a change, a request) through its steps, up to an output and, when the output must take effect, a review gate. The same run is shown in two places: the assistant panel, where a person talks and acts, and the object page, which is the record everyone shares. The state, the steps, the output and the gate are the same data in both; only the depth differs. Example on these boards: the four TOGAF agents of a change (analysis, draft, review, implementation).

One run, two views
  • Panel: milestones of the runs this conversation started or that wait for you. Act at the gate without leaving the chat.
  • Page: every run of the object in process order, all steps, the activity and the output. Link to it, review there, keep the history.
  • Header indicator: from anywhere, what runs and what waits for you.
  • Output viewer: the full output of one run, opened from either view; it has its own address.
Use the panel version when
  • the person started the agents from the conversation, or asked about them there;
  • the next thing they need is a decision (a gate) or a short answer;
  • a run reaches a milestone: started, finished, waiting, failed. One line each, never one per step.
Use the page version when
  • several people follow or review the object;
  • you need every step, the activity, earlier runs or the output in full;
  • the run was started by a signal, a schedule or another agent, not by a conversation.
Rules
  • An agent output that takes effect passes a person first (PRI-01): the run stops at a gate, nothing is applied before.
  • Only the named approver sees the gate buttons; everyone else sees “Waiting for <name>”.
  • Teal means an agent is working, nothing else. Waiting for you is violet with a 2 px border, the review gate of the notation.
  • A state is a word and a glyph, never a colour alone.
  • A new run never overwrites an old one: run 2 is listed after run 1, which shows “Cancelled · superseded”.

Accessibility
  • Milestone rows sit in the conversation’s aria-live="polite" region; step ticks are not announced.
  • The strip is role="status"; the gate is a group named by its question.
  • Working dots are aria-hidden and stop with prefers-reduced-motion; the word Running stays.
  • Stage cards are buttons with aria-pressed for the selected run; tabs of the viewer are a tablist.
